# 菲比随机互动

独立 AstrBot 插件，面向 **AstrBot v4.29.1**。管理员在群里开启后，由程序选择执行时间和行为，
不是让模型假装设置了定时器。不会修改菲比表情包仓库或 AstrBot 现有配置。

## 安装

推荐在 **AstrBot插件管理 → 从链接安装** 中填写：

```text
https://github.com/ifddis/feibi-meme-pack/tree/plugin-random-events
```

这是专用于插件交付的独立分支，不是表情包分支；不要在 meme_manager 的表情包安装框中填写。
也可下载本分支 `downloads/` 中的插件 ZIP 后使用本地上传安装。
主仓库的 main 分支和表情包不受本插件分支影响。


1. 在 AstrBot 插件管理中使用“上传/本地安装”安装 `astrbot_plugin_random_events-0.1.0.zip`。
   v4.29.1 的后台支持插件 ZIP 上传安装。没有看到上传入口时，可使用下方手动方式。
2. 安装所需依赖只有 `tzdata`（Windows 时区支持），由插件安装流程读取 requirements.txt。
3. 在 AstrBot 当前配置的 **管理员列表 `admins_id`** 中添加你的 UID。使用 `/sid` 获取 UID，
   管理员填 UID，不能填 UMO；QQ群主身份或昵称“管理员”不替代 AstrBot 管理员身份。
4. 在插件配置页确认时区、允许时段、每日上限和表情路径。初次安装所有群的任务默认关闭。
5. 到目标群 **@机器人** 使用下面的命令。

手动安装：将 ZIP 内容解压到 AstrBot 安装目录的
`data/plugins/astrbot_plugin_random_events/`，确认该目录下直接有 `main.py`、`engine.py` 和
`metadata.yaml`，不要再套一层同名目录。依赖应安装到运行 AstrBot 的同一个 Python 环境，
然后在后台重载插件或重启 AstrBot。Docker 部署应使用实际映射的数据目录。

## 管理命令

所有命令都由代码调用 `event.is_admin()` 校验，**只允许 AstrBot 管理员在当前群执行**。
不接受“我是管理员”等文字声明，也不把控制能力暴露为模型工具。

| 命令 | 行为 |
| --- | --- |
| `/随机事件 开启` | 开启当前群；第一次自动互动也要等到下一次调度，不会立即发言 |
| `/随机事件 关闭` | 停止当前群后续互动；生成中的任务发送前再次检查开关 |
| `/随机事件 状态` | 查看开关、下次时间、今日尝试、连续失败及本地表情数量 |
| `/随机事件 立即触发` | 立即抽取一个行为；即使自动任务关闭也可手动测试 |
| `/随机事件 间隔 60 180` | 当前群每次随机等待60～180分钟；不自动开启 |
| `/随机事件 固定间隔 120` | 当前群每次等待120分钟；不自动开启 |
| `/随机事件 定时 10:00,15:00,20:00` | 当前群每天这些时刻各随机选择一个行为；不自动开启 |
| `/随机事件 帮助` | 显示指令说明 |

首次测试建议先执行 `/随机事件 状态`，再执行 `/随机事件 立即触发`。
**手动触发也遵守允许时段、每日上限和近期活跃条件。** 夜间测试时，可临时将允许时段起止小时都设为 `0`
表示全天，测试结束后恢复。立即触发会另外回复执行结果，自动任务每次只发送一条行为消息。

## 默认行为

| 设置 | 默认值 |
| --- | --- |
| 每次间隔 | 随机60～180分钟，从上次执行结束重新计算 |
| 行为权重 | 聊天50、表情30、提问20 |
| 每群每日尝试上限 | 3次，按 Asia/Shanghai 日期计算 |
| 允许时段 | 09:00～23:00，23点起不发送 |
| 近期活跃要求 | 不要求（activity_minutes=0）；设120可要求两小时内收到过成员消息 |
| 连续失败 | 达3次暂停当前群，检查后由管理员重新开启 |
| 文字上下文 | 最近20条实际收到的文本，不是补拉QQ历史 |

也支持“每天指定时刻”模式；例如 `/随机事件 定时 20:00` 后再 `/随机事件 开启`，
表示每天20点抽取一个行为。多个时刻用逗号分隔。时刻受允许时段约束，完全不在允许时段内的设置会被拒绝；
达到每日上限后等待次日的有效时刻，不会提前到其他时间补发。

权重由程序随机抽取，而不是模型自行决定行为。权重0表示不使用该行为。
表情目录没有可用图片时跳过表情行为，剩余正权重按比例抽取；如果只启用表情权重却没有图片，会记录失败。
允许时段可跨午夜，例如22～7；起止相同表示全天。后台每15秒检查到期任务，因此可能有少量调度延迟。

**每日上限计算触发尝试，不仅是成功发送。** 模型失败、发送失败或发送结果不确定也计数；
不会立即重试，不会因关闭再开启而清零。连续失败暂停后，重新开启只清除连续失败状态，不清除当天尝试次数。
调度开关、下次时间、当前群间隔和计数写入 SQLite，进程重启后保留；过期任务最多执行一次，不追补多条。

“默认模式/间隔/每日时刻”配置仅用于新绑定群，已有群请用对应命令修改；其他全局插件设置在重载后生效。
配置热更新或插件卸载时会取消本插件后台任务。已经提交给平台的消息无法撤回；不承诺严格的恰好一次投递。

## 文字与表情如何发送

- 文字直接调用 AstrBot 当前群的聊天模型，留空 provider_id 即沿用你的 DeepSeek，不要重复填写 API 密钥。
- 可在插件配置中填写随机文字人设；它独立于 AstrBot 原有人格，不会修改原人格。
- 生成时只提供有限的群消息参考，不开放模型工具；因此随机池不包含系统命令、配置修改或其他任意操作。
- 表情直接读取**已经安装在本机的内容包**，使用 AstrBot 图片组件发送，不依赖模型输出表情占位符。
- 默认自动寻找 `data/plugin_data/meme_manager/packs/ifddis.feibi-chibi/`。
- 找不到时，在 `meme_pack_dir` 填**含 manifest.json 和 memes/ 的包根目录**，不要填 GitHub 链接。
- 默认从 happy、cute、affection、dancing 分类抽取，分类可在配置页修改。
- 不下载上游图片、不转换 GIF、不执行图片目录中的脚本；拒绝越界符号链接、非图片签名和超过25MB的文件。

表情发送仍依赖 QQ 适配器可用的图片发送能力。聊天生成和主动发送沿用 AstrBot 的正常接口，
不会模拟过期的被动回复凭证，也不会绕过平台权限或配额。

## QQ 官方机器人与实际送达

v4.29.1 的 QQ 适配器需要从收到的事件恢复群会话场景，因此**重启后先在目标群 @机器人发送一次
`/随机事件 状态`**。恢复前插件会等待，不会盲目消耗当天次数。

状态中“发送接口正常返回”只表示 `Context.send_message` 返回了 True；该值首先表示匹配了平台，
不是 QQ 的送达回执。以群里实际出现消息为准，必要时查看 QQ 适配器日志。
不会因模型说“已经发送”就计为成功：本插件实际调用发送接口，并独立记录结果。

AstrBot 原有“概率主动回复”和“未来任务”与本插件分别运行。
如果原主动回复概率仍设为1，仍可能每条消息都回复；建议改为较低概率或关闭，避免和本插件互动叠加。
本插件的权限检查仅覆盖自己的管理命令，不会改变其他插件或内置工具的权限。

## 本地记录

数据放在 `data/plugin_data/astrbot_plugin_random_events/state.sqlite3`，不写入插件代码目录。
只缓存已开启群的实际收到文本（不含机器人自身消息），每群最多50条，每条最多1000字；
运行时每小时清理超过7天的记录，启动时也清理。context_messages=0 时不缓存正文。
不记录密钥、不对外提供消息查询接口；模型只获得当前群的有限文本。
停机期间不会执行清理；需要彻底删除数据时，停用插件后删除该插件的数据目录，不要删除其他插件目录。
